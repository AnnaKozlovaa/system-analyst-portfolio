# Проектирование Интеграций

Добро пожаловать! В этом репозитории собраны мои практические учебные проекты.

---

## 🛠️ Навигация по проектам

### [Проект 1: REST API — Интеграция с платежным шлюзом (Сценарий подписок)](./project-1-rest/)
**Бизнес-кейс:** Автоматическое рекуррентное списание средств для онлайн-школы (модель подписки).
*   **Спроектировано:** Контекстная диаграмма (C4 Level 1), Sequence Diagram взаимодействия систем.
*   **Спецификации:** OpenAPI 3.0 (YAML) контракт для биллинга, JSON-схемы валидации ответов.
*   **Технические паттерны:** Идемпотентность транзакций (`Idempotency-Key` на базе UUID) для защиты от повторных списаний, аналитический справочник бизнес-ошибок (`insufficient_funds`, `card_expired`).
*   **Тестирование:** Коллекция запросов Postman с автоматическими JavaScript-тестами.

### [Проект 2: Kafka — Асинхронный сервис нотификаций](./project-2-kafka/)
**Бизнес-кейс:** Мгновенная отправка Push-уведомлений клиентам сети пиццерий при изменении статусов заказов на кухне.
*   **Спроектировано:** Data Flow архитектура очередей, Sequence Diagram (асинхронная Pull-модель консьюмера).
*   **Спецификации:** Структура асинхронного JSON-сообщения с метаданными (`event_id`, `event_type`).
*   **Технические паттерны:** Повышение надежности через цепочку обработчиков ошибок (Immediate Retry -> Retry Topic -> Dead Letter Queue), защита от дубликатов на стороне консьюмера (паттерн Idempotent Consumer с использованием кэша Redis по `event_id`).

### [Проект 3: gRPC — Микросервис расчета стоимости поездки](./project-3-grpc/)
**Бизнес-кейс:** Высоконагруженное внутреннее взаимодействие между Сервисом Заказов и Сервисом Ценообразования в такси для мгновенного расчета тарифной сетки.
*   **Спроектировано:** Протокол взаимодействия микросервисов по HTTP/2, Sequence Diagram интеграции с Гео-сервисом спроса.
*   **Спецификации:** Бинарный контракт в формате Protocol Buffers (`pricing.proto`) с использованием сложных структур и массивов (`repeated`).
*   **Технические паттерны:** Маппинг кастомных бизнес-ошибок валидации гео-координат на нативные gRPC status codes (`INVALID_ARGUMENT`, `UNAVAILABLE`) с использованием объекта `google.rpc.BadRequest`.
